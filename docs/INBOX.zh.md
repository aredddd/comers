# Comers 工作收件箱

每 10 秒检查飞书私聊、群聊 @ 和 Meegle 个人缺陷待办。普通轮询只调用 CLI，不运行模型；出现新消息或缺陷变化时，才交给 Codex 判断事项、关联会话和需要准备的产物。

## 启动

```bash
comers inbox init --state-dir /绝对路径/收件箱
comers inbox run --state-dir /绝对路径/收件箱
comers inbox status --state-dir /绝对路径/收件箱
```

开发工作区尚未安装到全局时，将 comers 替换为 node /工作区/dist/cli.js。初始化只生成配置，不启动服务。run 为前台常驻命令，退出或收到 SIGTERM 后停止。只读采样可以加 --once，不启动 AI。

配置、队列、执行工作区和审阅地址都放在指定目录；文件按本机私有权限保存。console.json 中的 url 是完整的本机审阅地址，包含访问凭据，勿转发或打印到共享日志。审阅界面只监听 127.0.0.1。

先用 lark-cli auth status --json --verify 和 meegle auth status --format json 检查登录；缺权限时优先按 CLI 提示登录或申请所需 scope，不使用浏览器自动化绕过授权。

## 来源与路由

- 私聊只处理其他用户发来的消息，群聊使用用户身份搜索 @ 自己的消息，排除本人和 bot。
- 消息保留 5 分钟重叠窗口，首次查询最近 30 分钟；已接收的消息按内容版本去重。首次 Meegle 扫描只建立基线，不处理存量待办；之后新分配的缺陷或描述、状态、评论变化触发处理。缺陷离开个人待办后仍继续跟踪。
- Meegle 默认只监控个人待办中的 issue、bug 类型。自定义缺陷类型先用 CLI 元数据确认实际 type key，再修改 defectTypeKeys；类型名不等于 type key。项目或视图级扫描不包含在个人待办来源中。
- routes 可显式配置 id、name、cwd、sourceSessionId、keywords。默认还从本机最近 30 个 Codex 会话发现候选；AI 从这些真实候选中判断，不自行编造目录或 session ID。匹配不到代码仓库时保留失败原因，补充路由后可重试。
- 源会话只通过 thread/read 读取上下文，每次处理新建执行会话，不写入源会话。跨消息和缺陷的明确关联可归并；不能仅因出现在同一群或仓库就合并事项。

codexModel 可指定收件箱使用的模型，只影响本收件箱，不修改用户全局 Codex 配置。留空时继承 CLI 的默认值；若默认值被账号拒绝，应查询本机 model/list，并通过实际调用确认可用后再配置，不能将模型目录当作账号可用性保证。

## 审阅

分析、代码、建议回复、追问和缺陷流转说明可以同时出现，各自产物独立通过或退回。修改文字后需重新通过。代码在隔离 worktree 中完成，不覆盖原工作区；界面可查看代码差异。

审阅通过本身不执行外发。点击「发送这条回复」才以用户身份回复原消息；点击「发布缺陷说明」才添加原缺陷评论。缺陷说明采用「问题原因、修复内容、回归要点」，待确认的原因和未执行的回归明确标注。

点击「创建草稿 MR」才提交、推送隔离分支并通过 gh 或 glab 创建草稿。目标分支为远端默认分支，已有该事项的 MR 时更新该 MR。发布前核对代码指纹；代码发生变化时需重新准备和审阅。不会自动合并、部署或改变缺陷状态。需要流转状态时，按 Meegle skill 查询真实可用状态，再由用户明确选择并授权执行。

消息版本、工单版本、队列和游标在一个原子快照中保存。新材料会撤销旧草稿及批准。写入结果未知时保留记录，不自动重试；尤其 Meegle 评论没有客户端幂等键，应先检查原工单。执行中断后保留会话和工作区，检查后再重试。

## 运行边界

当前 AI 并发为 1，采集与 AI 处理独立运行。采集请求不重叠；扫描超过 10 秒时，结束后再开始下一轮，不堆积。接口限流、暂时失败和授权过期会按来源退避，不推进失败来源的游标。

每仓库最多 5 个 linked worktree，主 checkout 不计。复用同事项的原工作区。已发布到 main/master 的本功能工作区，在确认远端提交包含该分支且工作区干净后自动回收；集成分支、脏工作区、异常或仍在处理的工作区保留。槽位不足时显示原因，不创建第 6 个，也不回收其他任务的工作区。

轮询周期不等于搜索索引可见延迟。高频 API 调用仍受平台额度约束；本实现没有宣称 10 秒内必定收到所有更新。当前只读取文本及接口返回的内容，不下载附件；需要附件或其他资料时应生成具体追问，不能把未知内容当成已验证事实。
