# Comers 工作收件箱

先读取 [使用说明](references/usage.md)，核对当前可执行文件是否支持 inbox 命令和用户配置的 state-dir。优先复用已有收件箱，不创建重复监听进程。存在 references/local-runtime.md 时一并读取，使用其中经过核对的本机路径。

- 使用 comers inbox status 检查各来源最近检查时间、错误及队列数量。不要根据旧记录宣称服务在线；前台服务启动日志也不能代替后续健康检查。
- 默认轮询 10 秒，轮询不运行模型；新材料才触发 AI。需要修改来源或周期时读取真实配置，不把普通 Codex 定时任务当作消息轮询器。
- 缺少授权优先通过 lark-cli 或 meegle 自行触发登录，不用浏览器绕过；不展示 token、消息正文或完整身份标识到诊断报告。
- 路由失败时核对真实仓库目录和源 session ID。每次处理应新建执行会话，源 session 只读上下文。
- 产物按分析、代码、回复、追问、缺陷流转说明独立审阅；有新变化时重新审阅，不能复用旧批准。
- 缺陷修复说明采用「问题原因、修复内容、回归要点」，原因和验证情况按当前证据填写。批量事项不得套用示例中的业务结论。
- 审阅通过与执行发布分开。只有用户明确选择具体外发动作后，才发回复、发缺陷评论或创建草稿 MR。不要自动合并、部署或流转缺陷状态。已经有具体授权时不重复确认。
- 写入结果未知时先检查原消息、评论或 MR，禁止自动重试或直接修改 state.json 伪造发送成功。中断执行先检查新会话和工作区，再重试。
